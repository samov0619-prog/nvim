Markdown details                                            *markdown-details*

HTML-спойлеры в Markdown используют render-markdown.nvim и nvim-ufo.
Нужны установленные Tree-sitter-парсеры markdown и html.

При первом открытии обычный <details> свёрнут, <details open> раскрыт.
Атрибут open логический: open="false" тоже означает раскрытый блок.
Закрытая строка показывает текст <summary> и число скрытых строк.
Без summary используется заголовок Details. Незакрытые details и примеры
в блоках кода не получают автоматическое сворачивание спойлеров.

Управление (Normal mode):
    za      переключить состояние блока под курсором
    zo / zc раскрыть / свернуть
    zR / zM раскрыть / свернуть все folds, включая обычные Markdown-folds
    K       предпросмотр закрытого блока (иначе LSP hover)

В раскрытом блоке теги details/summary скрыты. На строке под курсором
исходная разметка видна благодаря существующему anti-conceal — для правки.
Для просмотра всего исходника: zR, затем :RenderMarkdown disable.
Вернуть оформление: :RenderMarkdown enable.
Ручное состояние folds сохраняется при перерисовке и редактировании;
изменение open не переключает уже открытый файл принудительно.

Первый рендер и folding могут выполниться в разном порядке. После закрытия
folds в том же окне видны более далёкие строки буфера, а topline и курсор
не меняются. render-markdown рендерит только видимую область с запасом;
WinScrolled не сообщает об изменении одной лишь нижней строки буфера.
Модуль config.markdown-viewport отслеживает границы области при redraw
и запрашивает рендер через публичный API уже вне redraw. Запросы объединены;
при неизменной области повторного рендера нет. Это относится не только
к заголовкам, но и к таблицам и остальным Markdown-декорациям.

Локальные проверки без сборки проекта (из каталога конфигурации): >
    nvim -n --headless -u NONE -i NONE -l tests/markdown-details.lua
    nvim -n --headless -u NONE -i NONE -l tests/markdown-viewport.lua
    nvim -n --headless -u NONE -i NONE -l tests/markdown.lua
<
